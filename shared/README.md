# `shared` directory

Cross-package contracts shared between the Fastify backend (`backend/`) and the React frontend (`frontend/`). Anything placed here must be safe to consume from both Node.js (ESM) and the Vite browser bundle.

## Layout

- `format/` — small pure formatters shared by API and UI where duplication would drift.
  - **`homeSystemNaming.ts`** — `homeSystemShortTag`, `sanitizePlayerSlug`, `formatPlanetCode`, `formatHomeSystemDisplayName` (EN/RU templates for home system titles and `{shortTag}-N` planet codes).
  - **`systemMapLayout.ts`** — deterministic flat home-system map layout helpers (`buildSystemMapLayouts`, `buildSystemMapOrbitGuideRadii`, `systemMapPlanetOrbitRadius`, `systemMapPlanetDistanceLy`, `sectorDeltaToSystemMapPoint`, `distancePointToSegment`, `systemMapPlanetDiscoveryRadius`) shared by the frontend renderer, expedition launch, cargo transfer previews, and expedition worker so pass-by scout discovery, same-system colonizer ETA, and same-system cargo ETA use the same route geometry and size-based planet footprint as the UI, with a minimum practical corridor for small worlds. Planet coordinates use stable one-planet-per-orbit slots after biome ordering, while orbit guide radii ignore obfuscated `unknown` placeholders so hidden bodies do not create artificial outer rings.

- `config/` — progression catalogs consumed by both Node and Vite bundles where duplication would drift (research gates for buildings; full tech tree).
    - **`buildingUpgradeEconomy.ts`** — shared building upgrade economics: global **L10** cap, Command Center type id, 1.6 cost / 1.8 time multipliers, L6+ extra material kits, and helper functions for backend spending plus frontend previews.
    - **`buildingResearchGates.ts`** — `ResearchUnlockRequirement` plus `BUILDING_RESEARCH_GATES` (imported through `backend/src/config/research-unlocks.ts` on the API side and directly by Cosmic build previews). Basic `battery` / `solar_plant` energy infrastructure stays ungated at Energy level 0, while `wind_turbine` and `fuel_generator` require Energy research.
    - **`shipResearchGates.ts`** — `SHIP_RESEARCH_GATES` maps ship hull ids to required completed research tiers, shared by backend `POST /ships/build` and the frontend shipyard planner so blockers such as `cargo_light` requiring Logistics L1 stay visible before construction.
    - **`expeditionRouting.ts`** — shared route math for expedition previews and backend launch results: `ExpeditionRouteMode`, `JUMP_FUEL_RESOURCE_ID`, `JUMP_GATE_JUMP_FUEL_COST`, sector XY distance, required fuel, and ETA helpers used by local and Jump Gate routes.
    - **`productionRecipes.ts`** — `PRODUCTION_RECIPES`, `recipesForBuildingType`, and `findProductionRecipe`; canonical manual manufacturing recipes for smelter/refinery/fabricator/cryo buildings, refinery `jump_fuel` production from starter-system inputs, plus fuel-generator battery charging recipes.
    - **`researchCatalog.ts`** — canonical **8×5** research tree (`RESEARCH_CATALOG`, `RESEARCH_TECH_TREE`) including Energy and Weapons branches, typed energy generation/storage/efficiency effects, and minute/hour-scale timer curves for the one-active-research queue; import via `@shared/config/researchCatalog` from backend and frontend (Docker mounts `shared/` at `/app/shared`; backend code uses `@shared`, not `../../../shared`).
    - **`resourceExtractionRates.ts`** — `EXTRACTABLE_RESOURCE_RATES_PER_HOUR` and `extractionRateForResource`; canonical per-resource passive extraction rates so iron, silicon, aluminum, titanium, silver, gold, starter gases, oil, biomass, etc. do not all inherit the same building-level rate.
    - **`tutorialRewards.ts`** — `TUTORIAL_STEP_RESOURCE_GRANTS`, `TUTORIAL_COMPLETION_RESOURCE_GRANTS`, and EN/RU UI summaries for onboarding; consumed by `features/tutorial/service.ts` and the Cosmic `Tutorial` overlay.

- `types/` — TypeScript interfaces and Zod schemas for HTTP payloads, WebSocket events, and other cross-cutting structures.
    - **`locale.ts`** — shared locale contract: `SUPPORTED_LOCALES`, `Locale`, `DEFAULT_LOCALE`, `normalizeLocale`, and request/response DTOs for `PATCH /me/preferences`.
    - **`user.ts`** — `User` interface including **`preferredLocale`**, **`diamonds`** (premium balance), `rushPricing`, `homeSystem`, and onboarding fields (`tutorialStep`, `tutorialCompletedAt`).
    - **`auth.ts`** — `AuthResponse` for the login flow.
    - **`world.ts`** — `PlanetResource`, `Building`, `BuildingEnergyState`, `PlanetEnergyStatus`, `Planet`, `HomeSystem` interfaces for world/planet state (`PlanetResource.richness` carries the deposit level exposed by `/me`, `Building.selectedResourceId` carries the chosen extractor target, `Building.production.activeOrders` carries queued/paused production processes for slot cards, `HomeSystem.shortTag` optional wire field from `/me`, `Planet.isColonized` distinguishes discovered read-only bodies from buildable settlements, `Planet.energy` exposes battery charge/generation/consumption, and `Building.queueStartedAt` supports exact live progress).
    - **`buildings.ts`** — `BuildingType` interface (including optional catalog limits), `BuildBlockedReason` unions (including planet-resource, resource-selection, and deposit-limit blocks), request/response types for construction (including optional `selectedResourceId`), **`ChangeExtractorResourceRequest` / `ChangeExtractorResourceResponse`** for `POST /buildings/resource`, and **`RushBuildRequest` / `RushBuildResponse`** for `POST /buildings/rush`.
    - **`diamonds.ts`** — `RushPricing` plus `estimateRushDiamondCost`, mirroring backend rush pricing so the UI can tick countdown prices live alongside `/me` and queue **`rushPricing`** metadata (progressive curve `round((minutes^0.85) * rate)` with optional cap).
    - **`building-eligibility.ts`** — `resolveBuildBlockedReason`, `resolvePlanetResourceBlockedReason`, `resolveExtractorSelectionBlockedReason`, `resolveBuildingProducedResourceIds`, `resolveBuildingProductionRateForResource`, `selectableResourceIdsForExtractor`, and `formatBuildBlockedMessage` for shared server/client validation messaging around construction/upgrade gates (research → deps → per-planet/global caps → selected extractor resource → deposit limit → max level / Command Center cap). Optional `dependencyBuildings` narrows dependency checks when some rows are still in the initial build queue; selected mine/drill/pump/biomass producers use local deposit sets and per-resource extraction rates while processors keep fixed outputs. Current extractor classes are metals (`mine`), gases (`drill`), oil/methane (`oil_pump`), and water/biomass (`biomass_harvester`).
    - **`research.ts`** — `ResearchBranch`, `ResearchProgress` (including active-tier `startedAt`), `ResearchDefinition`, `StartResearchRequest` / `StartResearchResponse`, `RushResearchRequest` / `RushResearchResponse`, `ResearchRequirementRef`, localized `RESEARCH_BRANCH_LABELS` / `researchBranchLabel`, `RESEARCH_BRANCH_LABELS_EN`, and `ResourceId` union (includes gameplay resources such as `oil`, `fuel`, `jump_fuel`, `steel`, `electronics`, precious metals, starter gases, and tiered minerals) used by the tech tree and unlock messaging on backend/frontend.
    - **`ships.ts`** — `Ship` and `ShipType` interfaces, plus ship-queue/rush payloads (`ShipQueueItem` includes `queueStartedAt`, `RushShipBuildRequest`, `RushShipBuildResponse`) used by fleet construction ETA/progress + rush flows.
    - **`expeditions.ts`** — `LaunchExpeditionRequest`, `Expedition`, and `ExpeditionResult` interfaces, including `routeMode`, server-calculated `fuelRequired` / `jumpFuelRequired`, route `distance`, timer fields consumed by fleet/map UI, and the deprecated-compatible Jump Gate request/response shape for `/expeditions/jump`.
    - **`cargo.ts`** — `CargoTransferLoad`, `CargoTransferRouteMode`, `CargoTransferRequest`, `CargoTransferRoutePreview`, and `CargoTransferPreviewResponse` contracts for one-way cargo transfer orders and server-side route previews, including optional `routeMode='jump_gate'`, ETA, ordinary route `fuel`, and stored Jump Fuel costs; duplicate resource load lines are valid and aggregated by the backend.
    - **`multiplayer.ts`** — `PresenceEntityKind`, explicit `PresenceEntityType` / `PresenceEntityRelation` metadata, `SectorPresenceEntity`, `SectorPresencePayload`, and `SectorSystemAnchor` contracts for the sector-map APIs (`GET /multiplayer/systems` and `GET /multiplayer/sectors/:sx/:sy/:sz/presence`).
    - **`production.ts`** — production recipe summaries, preview/start payloads, structured block reasons, and production-process DTOs shared by `/resources/production/*` and the frontend production dialog; `ProductionOrderStatus` includes `paused`, and orders may carry `pausedAt` plus active `energyPerHour`.
    - **`jump-gate.ts`** — `JumpGateStateResponse` and supporting locked-reason, anchor, calibration, random-jump availability, known-destination DTOs (`source`, `lastVisitedAt`, safe per-body discovery/colony summaries), and random/known destination jump payloads for `/jump-gate/*`, including the stored Jump Fuel cost returned after travel.


## Conventions

- Use plain `.ts` modules with named exports. Do not import Node-only or DOM-only APIs from this folder.
- When you add a new contract, prefer Zod schemas plus `z.infer<typeof schema>` so both sides validate identical shapes at runtime when needed.
- The backend mounts this directory at `/app/shared` inside Docker (`docker-compose.yml`), so backend imports look like `../../../shared/types/<file>.js`. Both backend and frontend now support the `@shared` alias, which resolves to `shared/` in Docker and `../shared/` locally.
- Use `@shared/types/<file>.js` in the backend and `@shared/types/<file>` (or with `.js`) in the frontend.
- Update [`DOCUMENTATION.md`](../DOCUMENTATION.md) and the affected package READMEs whenever you publish a new shared type.
