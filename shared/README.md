# `shared` directory

Cross-package contracts shared between the Fastify backend (`backend/`) and the React frontend (`frontend/`). Anything placed here must be safe to consume from both Node.js (ESM) and the Vite browser bundle.

## Layout

- `format/` — small pure formatters shared by API and UI where duplication would drift.
  - **`homeSystemNaming.ts`** — `homeSystemShortTag`, `sanitizePlayerSlug`, `formatPlanetCode`, `formatHomeSystemDisplayName`, and `formatCommonSystemDisplayName` (EN/RU templates for owned home-system titles, neutral common-system titles, and `{shortTag}-N` planet codes).
  - **`systemMapLayout.ts`** — deterministic flat home-system map layout helpers (`buildSystemMapLayouts`, `buildSystemMapOrbitGuideRadii`, `systemMapPlanetOrbitRadius`, `systemMapPlanetDistanceLy`, `systemMapJumpGatePoint`, `systemMapPointDistanceLy`, `sectorDeltaToSystemMapPoint`, `distancePointToSegment`, `systemMapPlanetDiscoveryRadius`) shared by the frontend renderer, expedition launch, cargo transfer previews, and expedition worker so pass-by scout discovery, same-system colonizer ETA, same-system cargo ETA, fixed Jump Gate marker placement, and gate-leg route fuel use the same route geometry and size-based planet footprint as the UI, with a minimum practical corridor for small worlds. Planet coordinates use stable one-planet-per-orbit slots after biome ordering, while orbit guide radii ignore obfuscated `unknown` placeholders so hidden bodies do not create artificial outer rings; anomalous common-world variants (`toxic`, `metallic`, `energy`) share the outer-orbit tier.

- `config/` — progression catalogs consumed by both Node and Vite bundles where duplication would drift (research gates for buildings; full tech tree).
    - **`buildingUpgradeEconomy.ts`** — shared building upgrade economics: global **L10** cap, Command Center type id, 1.6 cost / 1.8 time multipliers, L6+ extra material kits, and helper functions for backend spending plus frontend previews.
    - **`buildingResearchGates.ts`** — `ResearchUnlockRequirement` plus `BUILDING_RESEARCH_GATES` (imported through `backend/src/config/research-unlocks.ts` on the API side and directly by Cosmic build previews). Basic `battery` / `solar_plant` energy infrastructure stays ungated at Energy level 0, while `wind_turbine`, `fuel_generator`, and late `atomic_reactor` construction require Energy research.
    - **`shipResearchGates.ts`** — `SHIP_RESEARCH_GATES` maps ship hull ids to required completed research tiers, shared by backend `POST /ships/build` and the frontend shipyard planner so blockers such as `cargo_light` requiring Logistics L1, `recon_probe` requiring Jump Drive L1, medium/heavy combat lines requiring Weapons III/IV, shield ships requiring Energy II–IV, and heavy rocket carriers requiring Weapons V stay visible before construction.
    - **`expeditionRouting.ts`** — shared route math for expedition previews and backend launch results: `ExpeditionRouteMode`, `JUMP_FUEL_RESOURCE_ID`, the 50-unit `JUMP_GATE_JUMP_FUEL_COST`, sector XY distance, required fuel, and ETA helpers used by local and Jump Gate routes. `isOneWayShipRole` and `isOneWayExpedition` keep the frontend preview and backend launch in lockstep on which roles deploy one-way at the destination (`combat`, `support`, `shield`, `missile`) and which still round-trip.
    - **`productionRecipes.ts`** — `PRODUCTION_RECIPES`, `recipesForBuildingType`, and `findProductionRecipe`; canonical manual manufacturing recipes for smelter/refinery/fabricator/cryo buildings, including expensive `silicon_carbide` fabrication from home-system materials, refinery `jump_fuel` production from starter-system inputs, plus fuel-generator battery charging recipes.
    - **`researchCatalog.ts`** — canonical **8×5** research tree (`RESEARCH_CATALOG`, `RESEARCH_TECH_TREE`) including Energy and Weapons branches, Logistics copy that calls out +5 colony slots per level, typed energy generation/storage/efficiency effects, and minute/hour-scale timer curves for the one-active-research queue; import via `@shared/config/researchCatalog` from backend and frontend (Docker mounts `shared/` at `/app/shared`; backend code uses `@shared`, not `../../../shared`).
    - **`resourceExtractionRates.ts`** — `EXTRACTABLE_RESOURCE_RATES_PER_HOUR` and `extractionRateForResource`; canonical per-resource passive extraction rates so iron, silicon, aluminum, titanium, silver, gold, starter gases, oil, antimatter, biomass, etc. do not all inherit the same building-level rate.
    - **`tutorialRewards.ts`** — tutorial step ids, one-time 100-diamond reward constants, claimed-reward bitmask helpers, and EN/RU UI summaries for onboarding; consumed by `features/tutorial/service.ts` and the Cosmic `Tutorial` overlay.

- `types/` — TypeScript interfaces and Zod schemas for HTTP payloads, WebSocket events, and other cross-cutting structures.
    - **`analytics.ts`** — shared analytics event taxonomy for `P4-ANA-001`: stable event names, categories, frontend/backend surface ownership, safe property allowlists, `isKnownAnalyticsEventName`, and `sanitizeAnalyticsProperties`. Backend/frontend analytics emitters import this file so event names and privacy filtering cannot drift.
    - **`locale.ts`** — shared locale contract: `SUPPORTED_LOCALES`, `Locale`, `DEFAULT_LOCALE`, `normalizeLocale`, and request/response DTOs for `PATCH /me/preferences`, including optional notification preference updates.
    - **`notifications.ts`** — shared Telegram notification categories, default enabled preferences, normalization helpers, and notification-type-to-category mapping used by `/me/preferences`, the frontend Profile menu, and the backend notification worker.
    - **`entity-labels.ts`** — localized, user-facing labels/descriptions for resource, building, and ship ids plus safe fallback humanization and insufficient-resource copy. Backend error payloads and frontend Cosmic fallback labels/descriptions use this file so raw slugs do not leak into gameplay text; starter military resource ids display as Silver Steel and C/SiC Composite.
    - **`user.ts`** — `User` interface including **`preferredLocale`**, **`notificationPreferences`**, **`diamonds`** (premium balance), `rushPricing`, `homeSystem`, `colonization` summary (active colony count, Logistics-scaled cap, cooldown, and per-level slot increase), and onboarding fields (`tutorialStep`, `tutorialCompletedAt`, `tutorialRewardsClaimed`).
    - **`tutorial.ts`** — tutorial sync/claim response contracts and the `{ stepId }` claim request shared by `/tutorial/sync`, `/tutorial/claim`, and the onboarding overlay.
    - **`auth.ts`** — `AuthResponse` for the login flow.
    - **`world.ts`** — `PlanetResource`, `Building`, `BuildingEnergyState`, `PlanetEnergyStatus`, `Planet`, `HomeSystem` interfaces for world/planet state (`PlanetResource.richness` carries the deposit level exposed by `/me`, `Building.selectedResourceId` carries the chosen extractor target, `Building.production.activeOrders` carries queued/paused production processes for slot cards, `HomeSystem.shortTag` optional wire field from `/me`, `Planet.isColonized` distinguishes discovered read-only bodies from buildable settlements, `Planet.energy` exposes battery charge/generation/consumption, and `Building.queueStartedAt` supports exact live progress).
    - **`buildings.ts`** — `BuildingType` interface (including optional catalog limits), `BuildBlockedReason` unions (including planet-resource, resource-selection, and deposit-limit blocks), request/response types for construction (including optional `selectedResourceId`), `BuildingQueueItem` metadata returned by build/upgrade starts for optimistic countdown replacement, **`ChangeExtractorResourceRequest` / `ChangeExtractorResourceResponse`** for `POST /buildings/resource`, and **`RushBuildRequest` / `RushBuildResponse`** for `POST /buildings/rush`.
    - **`diamonds.ts`** — `RushPricing` plus `estimateRushDiamondCost`, mirroring backend rush pricing so the UI can tick countdown prices live alongside `/me` and queue **`rushPricing`** metadata (progressive curve `round((minutes^0.85) * rate)` with optional cap).
    - **`building-eligibility.ts`** — `resolveBuildBlockedReason`, `resolvePlanetResourceBlockedReason`, `resolveExtractorSelectionBlockedReason`, `resolveBuildingProducedResourceIds`, `resolveBuildingProductionRateForResource`, `selectableResourceIdsForExtractor`, and `formatBuildBlockedMessage` for shared server/client validation messaging around construction/upgrade gates (research → deps → per-planet/global caps → selected extractor resource → deposit limit → max level / Command Center cap). Optional `dependencyBuildings` narrows dependency checks when some rows are still in the initial build queue; selected mine/drill/pump/biomass producers use local deposit sets and per-resource extraction rates while processors keep fixed outputs. Current extractor classes are solid mineral deposits including ice (`mine`), gases (`drill`), oil/methane (`oil_pump`), and water/biomass (`biomass_harvester`); `silicon_carbide` is intentionally produced through fabrication recipes instead of mined.
    - **`research.ts`** — `ResearchBranch`, `ResearchProgress` (including active-tier `startedAt`), `ResearchDefinition`, `StartResearchRequest` / `StartResearchResponse`, `RushResearchRequest` / `RushResearchResponse`, `ResearchRequirementRef`, localized `RESEARCH_BRANCH_LABELS` / `researchBranchLabel`, `RESEARCH_BRANCH_LABELS_EN`, and `ResourceId` union (includes gameplay resources such as `oil`, `fuel`, `jump_fuel`, `steel`, `electronics`, precious metals, starter gases, and tiered minerals) used by the tech tree and unlock messaging on backend/frontend.
    - **`resources.ts`** — shared resource group contracts for advanced Common Pool materials, radioactive resources used by abstract atomic power gameplay, and manufactured military components (internal ids `military_alloy` / `military_composite`, displayed as Silver Steel / C/SiC Composite) so backend audits and UI logic can reference the same sets.
    - **`ships.ts`** — `Ship` and `ShipType` interfaces, including own ship tanks (`fuel` / `jumpFuel`), refueler reserve balances (`refuelFuel` / `refuelJumpFuel`), and catalog reserve capacities (`refuelFuelCapacity` / `refuelJumpFuelCapacity`), plus ship build/queue/rush payloads (`BuildShipResponse`, `ShipQueueItem` includes `queueStartedAt`, `RushShipBuildRequest`, `RushShipBuildResponse`) and localized ship-build blocker formatting used by fleet construction ETA/progress + rush flows, including combat stats/shield/missile payload fields from `combat.ts` and `spaceport` missing/full landing-capacity errors that may include docked ships, inbound landings, or return-trip reservations.
    - **`refuel.ts`** — `RefuelRequest` / `RefuelResponse`, typed refuel blocker codes, and EN/RU formatter helpers for `/ships/refuel` so backend validation and fleet UI errors stay synchronized. Responses include the refueler's own tanks plus remaining support reserve after a transfer.
    - **`combat.ts`** — combat stat contracts for ship/building target classes, sustained damage profiles, engagement ranges, persistent shield hooks (`capacity`, `radius`, `currentHp`, downtime, delay, recharge), abstract missile payload profiles used by rocket carriers, and the Weapons V abstract nuclear payload profile/cost/cooldown contract. Payloads store only game balance values such as damage, reload/cooldown, target classes, range, evasion counters and resource costs without real-world implementation detail.
    - **`expeditions.ts`** — `LaunchExpeditionRequest`, `Expedition`, and `ExpeditionResult` interfaces, including `routeMode`, optional Jump Gate scout target-system point coordinates (`targetSystemX` / `targetSystemY`), server-calculated `fuelRequired` / `jumpFuelRequired`, route `distance`, split origin/target gate distances, timer fields consumed by fleet/map UI, localized launch blocker formatting for target `spaceport` slot failures and missing gate target points, return-trip reservation metadata stored in expedition results, and the deprecated-compatible Jump Gate request/response shape for `/expeditions/jump`.
    - **`cargo.ts`** — `CargoTransferLoad`, `CargoTransferRouteMode`, `CargoTransferRequest`, `CargoTransferRoutePreview`, and `CargoTransferPreviewResponse` contracts for one-way cargo transfer orders and server-side route previews, including optional `routeMode='jump_gate'`, ETA, ordinary route `fuel`, and stored Jump Fuel costs; duplicate resource load lines are valid and aggregated by the backend.
    - **`multiplayer.ts`** — `PresenceEntityKind`, explicit `PresenceEntityType` / `PresenceEntityRelation` metadata, `SectorPresenceEntity`, `SectorPresencePayload`, and `SectorSystemAnchor` contracts for the sector-map APIs (`GET /multiplayer/systems` and `GET /multiplayer/sectors/:sx/:sy/:sz/presence`).
    - **`production.ts`** — production recipe summaries, preview/start payloads, structured block reasons, and production-process DTOs shared by `/resources/production/*` and the frontend production dialog; `ProductionOrderStatus` includes `paused`, and orders may carry `pausedAt` plus active `energyPerHour`.
    - **`jump-gate.ts`** — `JumpGateStateResponse` and supporting locked-reason, anchor, calibration, random-jump availability, known-destination DTOs (`shortTag`, `source`, `lastVisitedAt`, deterministic `seed`, total `planetCount`, safe per-body discovery/colony summaries, and mined-resource rows for discovered public planets), and random/known destination jump payloads for `/jump-gate/*`, including the stored Jump Fuel cost returned after travel; random discovery consumes a `recon_probe`, opens one public common-pool system into the player's known-destination list, while known gate routes are used by ordinary scout, colonizer, and cargo flows.


## Conventions

- Use plain `.ts` modules with named exports. Do not import Node-only or DOM-only APIs from this folder.
- When you add a new contract, prefer Zod schemas plus `z.infer<typeof schema>` so both sides validate identical shapes at runtime when needed.
- The backend mounts this directory at `/app/shared` inside Docker (`docker-compose.yml`), so backend imports look like `../../../shared/types/<file>.js`. Both backend and frontend now support the `@shared` alias, which resolves to `shared/` in Docker and `../shared/` locally.
- Use `@shared/types/<file>.js` in the backend and `@shared/types/<file>` (or with `.js`) in the frontend.
- Update [`DOCUMENTATION.md`](../DOCUMENTATION.md) and the affected package READMEs whenever you publish a new shared type.
