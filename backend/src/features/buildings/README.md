# `backend/src/features/buildings` directory

Construction queues, demolitions, and building-type reads on player planets.

## Files

- **`routes.ts`** — Registers JWT-protected `GET /types`, `POST /build`, `POST /upgrade`, `POST /demolish`, `POST /sync/:planetId`, `GET /queue` (includes server-derived **`queueStartedAt`**, per-row **`rushCost`** snapshot, plus **`rushPricing`** meta), and **`POST /rush`** (`{ buildingId }`) under `/buildings`.
- **`service.ts`** — `BuildingService` owns catalog reads plus transactional **`build`**, **`upgrade`**, **`demolish`**, **`rushQueuedBuilding`** (spend `users.diamonds`, then **`finalizeBuildingConstruction`** without Telegram notification), **`syncPlanetBuildings`**, **`finalizeBuildingConstruction`**, and planet-aware regen aggregation for producers. `getBuildingTypes()` returns rows sorted by canonical seed order (unlock progression). **`build`** first requires an active settlement from `features/colonies/ownership.ts` (capital Command Center or colony record), so merely discovered planets remain read-only until a colonizer arrives. It then passes two building snapshots into eligibility: full rows for per-planet caps, and a dependency snapshot that omits rows still in the initial construction queue (`queueAction === 'build'`) so unfinished builds do not unlock dependents early. After generic gates, it applies shared planet-resource gates from `@shared/types/building-eligibility`: mines need a metal deposit, drills need a fluid/gas/ice deposit, and oil-pump/refinery chains need oil. Producer finalization recalculates only resources that the completed building can actually produce on that planet (extractors use local deposits, processors keep fixed outputs) and ignores buildings still in the initial build queue. `syncPlanetBuildings()` also clears stale pending `building_done` notifications for just-synced rows so active players do not get redundant Telegram pushes from worker races. **`upgrade`** scales the next level’s resource cost by **1.6^currentLevel** (per resource, floored) and upgrade duration by **1.8^currentLevel × baseTimeSec** before research speed modifiers; demolition refunds sum historical upgrade spends under the same cost curve (50% floor). The seeded Command Center now has a basic `iron`/`carbon`/`silicon` `baseCost`, so upgrades are no longer free.
- **`building-operation-error.ts`** — `BuildingOperationError` carries deterministic `{ code, details }` pairs mirrored by `@shared/types/buildings` (`BuildBlockedReason`).
- **`count-user-buildings.ts`** — `countUserBuildingsOfType` is the single account-wide counter used when enforcing **`building_types.max_global`** at construction time; it counts both home-system settlements and colony planets.
- **`upgrade.ts`** — legacy/alternate upgrade entry point kept aligned with `BuildingService.upgrade` multipliers (**1.6^level**, **1.8^level**); HTTP routes call `BuildingService` directly.
- **`buildings.test.ts`**, **`service.test.ts`**, **`upgrade.test.ts`**, **`rush.test.ts`**, **`eligibility.test.ts`** — Vitest coverage over transactional flows plus pure eligibility ordering rules shared with the frontend.

## Adding limits / prerequisites

1. Extend **`building_types`** through Drizzle (`backend/src/db/schema/buildings.ts`) + migrations + `catalog-rows.ts` seeds (`max_per_planet`, `max_global`, deps JSON).
2. Wire shared eligibility logic (`@shared/types/building-eligibility`) inside **`service.ts`** right after queue-cap checks so the backend rejects duplicates atomically before charging resources.
3. Mirror counters offline via **`tools/balance-sim/src/catalog.ts`** when production timings/deps change.
4. Research-gated builds consume **`BUILDING_RESEARCH_GATES`** from **`shared/config/buildingResearchGates.ts`** (re-exported through `backend/src/config/research-unlocks.ts`) so UI previews cannot drift from enforcement order (`research → deps → per-planet → global`).
