# `backend/src/features/buildings` directory

Construction queues, demolitions, and building-type reads on player planets.

## Files

- **`routes.ts`** — Registers JWT-protected `GET /types`, `POST /build` (`{ planetId, typeId, slotIndex, selectedResourceId? }`), `POST /upgrade`, `POST /demolish`, `POST /sync/:planetId`, `GET /queue` (includes server-derived **`queueStartedAt`**, per-row **`rushCost`** snapshot, plus **`rushPricing`** meta), and **`POST /rush`** (`{ buildingId }`) under `/buildings`.
- **`service.ts`** — `BuildingService` owns catalog reads plus transactional **`build`**, **`upgrade`**, **`demolish`**, **`rushQueuedBuilding`** (spend `users.diamonds`, then **`finalizeBuildingConstruction`** without Telegram notification), **`syncPlanetBuildings`**, **`finalizeBuildingConstruction`**, and planet-aware regen aggregation for passive producers. `getBuildingTypes()` returns rows sorted by canonical seed order (unlock progression). **`build`** first requires an active settlement from `features/colonies/ownership.ts` (capital Command Center or colony record), so merely discovered planets remain read-only until a colonizer arrives. It then passes two building snapshots into eligibility: full rows for per-planet caps, and a dependency snapshot that omits rows still in the initial construction queue (`queueAction === 'build'`) so unfinished builds do not unlock dependents early. Extractor builds require a chosen `selectedResourceId`, validate it against local deposits, and reject starts when active/queued extractors already consume all `richness.value` sources for that resource. Producer finalization recalculates only resources that the completed building can passively produce on that planet; selected extractors produce only their saved resource, while processors produce through `production_orders`. Energy-affecting completions/demolitions also call `syncEnergyResourceRow` so battery charge/cap and solar/wind net generation are immediately reflected in `planet_resources.energy`. `syncPlanetBuildings()` also clears stale pending `building_done` notifications for just-synced rows so active players do not get redundant Telegram pushes from worker races. **`upgrade`** revalidates selected extractor deposit limits, scales the next level’s resource cost by **1.6^currentLevel** (per resource, floored), and scales upgrade duration by **1.8^currentLevel × baseTimeSec** before research speed modifiers; demolition refunds sum historical upgrade spends under the same cost curve (50% floor). The seeded Command Center now has a basic `iron`/`carbon`/`silicon` `baseCost`, so upgrades are no longer free.
- **`building-operation-error.ts`** — `BuildingOperationError` carries deterministic `{ code, details }` pairs mirrored by `@shared/types/buildings` (`BuildBlockedReason`).
- **`count-user-buildings.ts`** — `countUserBuildingsOfType` is the single account-wide counter used when enforcing **`building_types.max_global`** at construction time; it counts both home-system settlements and colony planets.
- **`upgrade.ts`** — legacy/alternate upgrade entry point kept aligned with `BuildingService.upgrade` multipliers (**1.6^level**, **1.8^level**); HTTP routes call `BuildingService` directly.
- **`buildings.test.ts`**, **`service.test.ts`**, **`upgrade.test.ts`**, **`rush.test.ts`**, **`eligibility.test.ts`** — Vitest coverage over transactional flows plus pure eligibility ordering rules shared with the frontend.

## Adding limits / prerequisites

1. Extend **`building_types`** through Drizzle (`backend/src/db/schema/buildings.ts`) + migrations + `catalog-rows.ts` seeds (`max_per_planet`, `max_global`, deps JSON).
2. Wire shared eligibility logic (`@shared/types/building-eligibility`) inside **`service.ts`** right after queue-cap checks so the backend rejects duplicates atomically before charging resources.
3. Mirror counters offline via **`tools/balance-sim/src/catalog.ts`** when production timings/deps change.
4. Research-gated builds consume **`BUILDING_RESEARCH_GATES`** from **`shared/config/buildingResearchGates.ts`** (re-exported through `backend/src/config/research-unlocks.ts`) so UI previews cannot drift from enforcement order (`research → deps → per-planet → global`). Energy infrastructure keeps `battery` / `solar_plant` available at level 0 and gates advanced `wind_turbine` / `fuel_generator` rows through Energy research.
