# `backend/src/features/expeditions` directory

Ship launch and expedition scheduling live here. The module accepts launch requests, validates ownership and resources, creates an `expeditions` row, and schedules the delayed completion job that future workers will consume.

## Files

- **`routes.ts`** — `expeditionsRoutes(app)` registers mutation-rate-limited and JSON-schema-validated endpoints:
  - `POST /` — launches a local expedition to a route point or a Jump Gate route to a known public destination. Local mode accepts `{ shipId, targetX, targetY, targetZ, cargoLoaded, fuelLoaded?, jumpFuelLoaded? }`; `routeMode='jump_gate'` accepts `{ shipId, destinationSystemId, cargoLoaded, fuelLoaded?, jumpFuelLoaded?, targetPlanetId?, targetSystemX?, targetSystemY? }` and server-resolves the target sector from `discovered_systems` instead of trusting arbitrary coordinates. Jump Gate routes are available to every non-logistics ship; logistics ships are rejected here and must use `/cargo/transfer`. Non-colonizer Jump Gate routes without a known `targetPlanetId` must provide a point on the opened destination system map. Fuel is calculated and reserved server-side from route distance and ship fuel consumption: launch planet -> Home Gate plus destination Gate -> selected point or planet; return-trip routes multiply ordinary fuel and Jump Fuel by two, while one-way deployments spend one Jump Fuel gate cost. The optional fuel fields let the client fill tanks beyond the mission minimum up to capacity. `targetPlanetId` is valid for recon surveys and colonizer deployments. Colonizers must provide a discovered, eligible target planet and reserve one-way fuel because a successful arrival consumes the ship into the new Command Center; combat/support/shield/missile Jump Gate routes may target an arbitrary destination-system point and stay there as a stationed fleet entry. Jump Gate colonizers skip the colony-distance gate while keeping discovery/protection/research/limit/cooldown checks.
  - `POST /jump` — deprecated-compatible Jump Gate entry point. Accepts `{ shipId, mode: 'random' }` for server-authoritative random jumps or `{ shipId, destinationSystemId }` for known destinations; legacy `{ targetSector }` requests are rejected without generating or visiting client-provided coordinates.
- **`launch.ts`** — `launchExpedition(userId, request)` performs the launch flow:
  - Loads the ship, its type, and current planet/system context.
  - Verifies the ship belongs to the caller and is `idle`.
  - Checks the ship is on a planet and that the ship can carry the requested cargo.
  - Calculates fuel from **sector XY** route distance (galactic plane; Z is ignored) × `ship_types.fuel_consumption`, from `systemMapPlanetDistanceLy` when a targeted local recon/colonizer launch stays inside the same system, or from split Jump Gate legs using `systemMapJumpGatePoint` / `systemMapPointDistanceLy` (launch planet -> Home Gate plus destination Gate -> selected map point or known planet), then spends the mission minimum plus optional tank top-up from the launch planet via `spendResources`. Return-trip gate routes reserve ordinary fuel and Jump Fuel for both jumps; colonizer and combat/support/shield/missile Jump Gate deployments reserve one-way route fuel and one Jump Fuel gate cost.
  - Validates `targetPlanetId` by role and route: local recon targets must be undiscovered home-system bodies, Jump Gate recon targets must belong to the selected known public destination, and colonizer targets must be discovered, unsettled, outside protected foreign Home Systems, and pass colonization gates. The colony-distance gate is enforced for local colonization but skipped for Jump Gate colonizer launches. A user with any active colonizer deployment is treated as on colonization cooldown until that mission can land and the normal cooldown window elapses. Ordinary non-survey target-planet launches call `features/ships/spaceport-capacity.ts` inside the launch transaction, lock the target planet, require completed `spaceport` capacity, and count docked/building ships plus already in-flight target-landing reservations before reserving a slot. Return-trip launches also reserve the origin `spaceport` slot until the ship comes home, while one-way colonizer deployments free their origin slot after departure and do not consume a target `spaceport` slot; colonizer arrival consumes the one-way mission and plants the Command Center without turning the ship around because cooldown or colony counts changed while it was in flight.
  - Creates the expedition row with `status='in_flight'`, updates the ship to `moving`, and computes `eta = distance × 60 / speed × engine_factor` with the current neutral engine factor. One-way point deployments transition to `status='stationed'` on arrival while keeping the ship in the destination combat space without a planet dock.
  - Allows combat/support/shield/missile ships that are already `stationed` at a Jump Gate destination point to launch again from that point. These relaunches keep the old stationed row from blocking orders, use the current public system as the origin, and can only spend fuel already in the ship tanks because no planet stockpile is available at a free-space point.
  - Optionally enqueues a BullMQ delayed job at `eta` when `ENABLE_BULLMQ=true`; otherwise the expedition poller and active-session sync complete due rows. Returns the created expedition plus queue metadata. Blocking responses carry structured codes/details and are localized by the route layer with ship/resource labels instead of raw ids.
- **`jump.ts`** — `jumpShip(userId, request, options?)` handles Jump Gate inter-sector jumps:
  - Verifies the selected ship is owned, idle, stationed on a planet, and funded with stored Jump Fuel.
  - Verifies the private Jump Gate is unlocked from completed `jump_drive` research level 1+ and is not calibrating.
  - Deducts 50 stored `jump_fuel` from the current planet inventory.
  - For random discovery, requires a `recon_probe`, grows the abstract Common Pool when empty, undersupplied for player count, exhausted by the player, or missing a first target without foreign ships, skips already-known public systems, enforces the 5-opened-public-systems base limit plus one extra random discovery per opened public system where the player has an active colony, and consumes the probe after opening exactly one public neutral system into the player's known-destination registry; private Home Systems are never valid jump targets.
  - For repeat travel, accepts only a known `destinationSystemId` from `discovered_systems`; ordinary idle ships can move through known gate routes, and manual sector coordinates are not accepted.
  - Upserts the system-level known destination with `source='random_jump'` and `lastVisitedAt`, but does not automatically discover every planet in the target system. Stored Jump Fuel blockers use the shared localized resource label.
- **`launch.test.ts`** — Vitest integration suite for standard launches, Jump Gate scout routing, Jump Gate colonizer launch/arrival, active-colonizer cooldown blocking, protected Home System rejection, insufficient fuel, and missing auth.
- **`jump.test.ts`** — Vitest integration suite for locked random jumps, deprecated manual coordinates, known-destination repeats, first-public-system foreign-ship filtering, common-pool target generation, random discovery limits, and foreign Home System suppression.

## Adding a new expedition action

1. Keep launch-specific domain logic in `launch.ts` and keep the route layer thin.
2. Reuse the existing `expeditions` table and extend the worker side later if the new action needs arrival processing.
3. Update this README and the parent [`backend/src/features/README.md`](../README.md) whenever you add a new file here.
